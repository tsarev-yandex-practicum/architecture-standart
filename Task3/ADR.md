### <a name="_qmphm5d6rvi3"></a>**Решение**

- [Диаграмма контекста](c4_context.png)
- [Диаграмма контейнеров](c4_containers.png)

Суть решения:
- Логика депозитов реализуется в новом контуре микросервисов Депозиты, а не в монолите интернет-банка
- Обмен с АБС - асинхронно через Kafka
- Мастер-данные (ставки, согласование, депозиты) остаются в АБС
- В контуре - копия ставок и реестр заявок
- Excel и почта из процесса исключаются
- Депозиты и накопительные счета проходят один процесс, далее оба называются депозитами

#### Компоненты

| Компонент | Технологии | Назначение |
| :- | :- | :- |
| Веб-приложение интернет-банка | ASP.NET MVC 4.5, .NET Framework 4.5 | Существующий монолит. Добавляются раздел Депозиты и вызовы API контура |
| API-шлюз депозитов | .NET | Единая точка входа в контур по HTTPS |
| Сервис ставок | .NET, PostgreSQL | Каталог продуктов, базовые и персональные ставки |
| Сервис заявок | .NET, PostgreSQL | Приём и хранение заявок с сайта и из интернет-банка |
| Сервис СМС | .NET, PostgreSQL | СМС-коды подтверждения и уведомления о статусе |
| Kafka | Apache Kafka | Новая корпоративная шина. Обмен ставками, заявками и статусами между системами |
| Интеграционный сервис АБС | Java, Spring Boot | Забирает заявки из Kafka в АБС, публикует ставки и статусы |
| БД АБС | Oracle, PL/SQL | Модули ставок и заявок, разграничение доступа между депозитами и кредитами |
| Клиент АБС | Delphi | Формы для ставок, согласования заявок и оценки риска |
| Сайт | PHP, React.js | Каталог депозитов и форма заявки |
| Система кол-центра | Java, Spring Boot | Приём заявок с сайта из Kafka, задачи на звонок |
| СМС-шлюз | - | Без изменений |

#### Интеграции

| Откуда -> куда | Протокол | Данные |
| :- | :- | :- |
| Сайт / монолит -> API-шлюз | REST, HTTPS | Ставки, заявки, СМС-код, статус |
| API-шлюз -> сервисы ставок и заявок | REST | Ставки, заявки, СМС-код |
| Сервис заявок -> сервис СМС | REST | Отправка и проверка СМС-кода |
| Сервисы контура -> свои БД | SQL | Копия ставок, заявки, журнал СМС |
| Сервис заявок -> Kafka | Kafka | Новые заявки |
| Kafka -> система кол-центра | Kafka | Заявки с сайта |
| Kafka -> интеграционный сервис АБС -> БД АБС | Kafka, SQL | Заявки из интернет-банка |
| БД АБС -> интеграционный сервис АБС -> Kafka | SQL, Kafka | Ставки и статусы |
| Kafka -> сервисы ставок, заявок и СМС | Kafka | Ставки, статусы |
| Сервис СМС -> СМС-шлюз | HTTPS | СМС-коды и уведомления |
| Система кол-центра -> АБС | Существующая интеграция | Обращения |
| Монолит интернет-банка -> БД АБС | Существующая интеграция | Счета клиента, платежи |
| АБС -> СМС-шлюз | Существующая интеграция | СМС о согласованной ставке по обращениям из кол-центра |

#### Обоснование

| Решение | Требования | Обоснование |
| :- | :- | :- |
| Kafka между интернет-банком и АБС | R3, +R4, +R6 | База АБС перегружена и масштабируется только вертикально. Kafka принимает пики заявок, АБС забирает их с допустимой скоростью |
| Ставки и согласование в АБС, копия ставок в контуре | UC1, UC2, UC4, UC5, UC7, F10, P1, R1 | Бэк-офис и данные о риске уже в АБС. Онлайн-каналы читают ставки из своей копии без нагрузки на АБС |
| Отдельный контур Депозиты | UC6, UC8, +R3, +R4, +R5 | Монолит не работает с Kafka, ядро обновляет подрядчик. СМС делает команда банка. В монолите остаются страницы и вызовы API |
| Стек .NET, Java, PostgreSQL | +R1, +R2, P3 | .NET знает команда интернет-банка. Сервисы не зависят от версии монолита и связаны с ним по REST. Java знают в команде АБС. PostgreSQL уже работает в банке в микросервисной системе кол-центра и не требует лицензии на каждый экземпляр БД в двух ЦОД. Новая технология одна - Kafka |
| Заявки с сайта через сервис заявок | UC3, UC4 | Один владелец заявок, сайту не нужна своя интеграция с Kafka |
| Несколько экземпляров сервисов в двух ЦОД | R1, R2, P3 | Новый контур масштабируется горизонтально. Монолит в MVP остаётся с переключением на резервный ЦОД |
| HTTPS | F11 | Шифрование трафика с сайта и из интернет-банка |
| Раздел Депозиты в существующих сайте и интернет-банке | U1, U2 | Клиент работает в привычном интерфейсе. Страницы делают команды сайта и интернет-банка по дизайн-системе банка |
| Платежи в MVP не меняются | P2 | Справочники платежей остаются в монолите, MVP их не затрагивает и не добавляет на них нагрузку. Требование вне рамок MVP |
| Документация решения | S1 | Этот ADR, диаграммы C4, описание API контура и сообщений в Kafka. Основа для подключения кредитов и других продуктов |

В разработке участвуют:
- Команда интернет-банка: раздел Депозиты в монолите, сервисы контура и их БД
- Команда АБС: модули ставок и заявок, формы в Delphi, интеграционный сервис
- Команда сайта: каталог депозитов и форма заявки
- Подрядчик кол-центра или Java-разработчики АБС: модуль приёма заявок из Kafka
- Инфраструктура: Kafka, PostgreSQL, балансировщики, сертификаты, размещение в двух ЦОД

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

- Депозиты в монолите с прямым доступом к БД АБС: дополнительная нагрузка на АБС, монолит не работает с Kafka, СМС пришлось бы делать через ядро подрядчика
- Синхронный REST API к АБС: каждый запрос нагружает АБС, доступность онлайн-каналов зависит от АБС, нет буфера на пики
- Ставки и согласование в новом сервисе: для специальной ставки и открытия депозита всё равно придётся ходить в АБС. К варианту можно вернуться при реализации автоматического расчёта ставок
- Сайт напрямую вызывает API системы кол-центра: зависимость от платформы подрядчика, нет единого владельца заявок, при недоступности кол-центра заявки теряются

**Недостатки, ограничения, риски**

- Нет опыта эксплуатации Kafka
- У команды интернет-банка нет опыта работы с PostgreSQL, систему кол-центра сопровождает подрядчик
- Ставки в контуре могут отставать от АБС
- При сбое ЦОД доступность обеспечена только для контура Депозиты, монолит интернет-банка остаётся в одном ЦОД
- Скорость обработки заявок зависит от числа сотрудников бэк-офиса
- У системы кол-центра нет доступа к ставкам, оператор узнаёт их у бэк-офиса
- Основной объём работ приходится на команду АБС и доработку кол-центра
- Персональные данные передаются через Kafka и хранятся в новых БД
