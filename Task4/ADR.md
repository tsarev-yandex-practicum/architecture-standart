### <a name="_qmphm5d6rvi3"></a>**Решение**

- [Диаграмма контекста](c4_context.png)
- [Диаграмма компонентов сервиса ставок](c4_component_rates.png)
- [Диаграмма компонентов сервиса ставок кол-центра](c4_component_call_center.png)
- [RoadMap](RoadMap.drawio)

Диаграммы покрывают только передачу ставок. Сайт, заявки, СМС и открытие депозита на них не показаны. Диаграммы компонентов есть для двух контейнеров, которые меняются в этом кейсе. Интеграционный сервис АБС не меняется.

Суть решения:
- Ставки по-прежнему вносят и хранят в АБС. Интеграционный сервис публикует в Kafka каталог продуктов, базовые и персональные ставки, как уже принято в MVP открытия депозитов
- Сервис ставок по-прежнему хранит онлайн-копию. Сайт и интернет-банк читают её
- Система кол-центра банка читает тот же поток и хранит только каталог продуктов и базовые ставки. Каждое принятое сообщение заменяет локальную копию целиком. Экран оператора читает эту копию
- Отдельный сервис выгрузки не создаётся. Сервис ставок после обновления копии сам формирует файл с каталогом продуктов и базовыми ставками и кладёт его на SFTP банка
- Система партнёра забирает файл и показывает ставки своим операторам
- Обращения кол-центра в АБС остаются как есть. Ставки через них не передаются

#### Компоненты

| Компонент | Технологии | Назначение                                                                                          |
| :- | :- |:----------------------------------------------------------------------------------------------------|
| Интеграционный сервис АБС | Java, Spring Boot | Публикует в Kafka каталог продуктов, базовые и персональные ставки                                                          |
| БД АБС | Oracle, PL/SQL | Мастер-система ставок                                                                               |
| Kafka | Apache Kafka | Доставка ставок от АБС к сервису ставок и к системе кол-центра. Кол-центр оставляет у себя каталог продуктов и базовые ставки                                      |
| Сервис ставок | .NET, PostgreSQL | Онлайн-копия ставок. Получатель ставок из Kafka, API ставок для сайта и интернет-банка без изменений. Новые компоненты: формирование файла после обновления копии и выгрузка на SFTP |
| БД ставок | PostgreSQL | Копия каталога продуктов, базовых и персональных ставок. В файл уходят только каталог продуктов и базовые ставки |
| SFTP банка | SFTP | Папка, куда сервис ставок кладёт файл и откуда его забирает партнёр                               |
| Сервис ставок кол-центра | Java, Spring Boot, PostgreSQL | Новый сервис. Получатель ставок из Kafka, локальная копия каталога продуктов и базовых ставок, API ставок для рабочего места оператора |
| Рабочее место оператора | Система кол-центра | Существующий интерфейс оператора. Добавляется экран ставок |
| Система партнёрского кол-центра | Внешняя система | Забор файла и показ ставок своим операторам                                                         |

#### Интеграции

| Откуда -> куда | Протокол | Данные |
| :- | :- | :- |
| БД АБС -> интеграционный сервис АБС -> Kafka | SQL, Kafka | Каталог продуктов, базовые и персональные ставки |
| Kafka -> сервис ставок -> БД ставок | Kafka, SQL | Обновление онлайн-копии |
| Kafka -> сервис ставок кол-центра | Kafka | Сообщение со ставками. Сервис сохраняет полный снимок каталога продуктов и базовых ставок |
| Рабочее место оператора -> сервис ставок кол-центра | REST | Каталог продуктов и базовые ставки для экрана |
| Сервис ставок -> SFTP банка | SFTP | Файл со снимком каталога продуктов и базовых ставок |
| SFTP банка -> система партнёра | SFTP | Файл со снимком каталога продуктов и базовых ставок |

#### Обоснование

| Решение | Требования | Обоснование |
| :- | :- | :- |
| Локальная копия в кол-центре из Kafka | UC1, UC2, 1, 2, 7, 8 | Система кол-центра уже на Java и уже читает Kafka. Экран оператора не зависит от сервиса ставок в момент звонка и не создаёт запросов к АБС |
| Файл из копии сервиса ставок | UC3, 3 | В момент выкладки в файле тот же каталог продуктов и те же базовые ставки, что показывает сайт. Персональные ставки интернет-банка в файл не входят |
| Выгрузка внутри сервиса ставок | 7 | Отдельный сервис не нужен. Формат файла и запись на SFTP остаются у команды, которая владеет онлайн-копией |
| SFTP, партнёр забирает файл сам | UC3, UC4, 4, 5 | Система партнёра принимает ставки только файлом. Банк её по API не вызывает. SFTP шифрует канал |
| В поток входят только базовые ставки | UC1, UC2, UC4, 6 | Задание требует консультацию по текущим ставкам банка. Персональные предложения к звонку в кол-центр не относятся |
| Публикация АБС без нового API | UC1, 1, 8 | Интеграционный сервис уже публикует ставки в Kafka. Новая точка чтения АБС для кол-центров не добавляется |

В разработке участвуют:
- Команда интернет-банка: формирование файла и выкладка на SFTP в сервисе ставок
- Подрядчик кол-центра или Java-разработчики АБС: приём ставок из Kafka, локальное хранение, экран оператора
- Инфраструктура: SFTP-сервер, папка, учётная запись партнёра
- Партнёр: забор файла и показ ставок своим операторам
- Команда АБС отдельную выгрузку файла не делает. Публикация ставок в Kafka входит в MVP открытия депозитов

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

- Кол-центр читает ставки прямо из базы АБС: при каждом просмотре экран оператора запрашивает Oracle. АБС наращивается только вертикально, а звонки после рекламы добавят ей запросы в те же часы, когда идут платежи и открытие депозитов. Пока АБС тормозит или недоступна, оператор остаётся без ставок.
- Кол-центр в момент звонка запрашивает ставки у интеграционного сервиса АБС: экран ждёт синхронный ответ. Всплеск звонков упирается в АБС, промежуточного буфера нет, и без ответа сервиса консультация по ставкам останавливается.
- Ставки по-прежнему рассылают почтой или Excel: бэк-офис выгружает таблицу и отправляет её в свой кол-центр и партнёру. Таблицу забывают разослать, и оператор называет ставку, которой в АБС и на сайте уже нет.
- Партнёр получает ставки через API: банк вызывает систему партнёра или партнёр сам забирает ставки вызовом API банка. Система партнёра принимает ставки только файлом, API-вызова нет.
- Свой кол-центр при каждом просмотре запрашивает сервис ставок и не хранит свою копию: экран каждый раз обращается в контур депозитов. Вместе с контуром гаснет и экран оператора, хотя для консультации ещё годится предыдущая копия. Отдельный синхронный вызов не нужен, система кол-центра уже забирает сообщения из Kafka.
- Файл на SFTP формирует интеграционный сервис АБС из базы АБС, а сайт по-прежнему показывает копию сервиса ставок. Файл и сайт обновляются двумя разными путями и совпадают, когда оба пути успешно отработали. Если сообщение в Kafka не дошло до сервиса ставок или файл не записался и повтор не сделали, разные ставки держатся до следующей успешной публикации. Формат файла, сервер SFTP и доступ партнёра в этом варианте ложатся на команду АБС, хотя копия, которую уже видит сайт, лежит в контуре депозитов.

**Недостатки, ограничения, риски**

- Копия в кол-центре отстаёт от АБС на время доставки через Kafka и может ненадолго разойтись с сервисом ставок. Если сообщение не дошло, у оператора остаётся предыдущий полный снимок до следующего успешного
- Партнёр видит новые ставки после выкладки файла и своего забора. Пока он сидит на прошлом файле, сайт уже может показывать новые ставки. Банк не задаёт момент забора и загрузки файла
- Если запись файла не прошла, партнёр остаётся на предыдущем снимке, а сайт показывает уже обновлённую копию
- Сервера SFTP в банке ещё нет: нужны сервер, папка, учётная запись партнёра и контроль, что файл действительно записан. Сервис ставок только кладёт туда файл
- Персональные предложения оператору недоступны. В консультацию входят только текущие ставки банка
